# 眼动追踪工具：基于浏览器的实时眼动追踪系统设计与实现

**日期**: 2026年5月

**版本**: 1.1

---

## 摘要

本项目是一个静态浏览器端眼动追踪工具。当前版本使用单个摄像头和本地 `webgazer.js` 进行眼动追踪，不再包含此前尝试过但已回退的双摄像头方案。实际实验中，参与者不是观看屏幕，而是观看另一处打印出来的横版 A4 校准纸和横版 A4 标识。因此系统会把校准点和追踪数据映射到一个内部横版 A4 纸面坐标系，再把热力图与视线轨迹叠加到上传的横版 A4 标识图像上。摄像头画面和眼动数据均在浏览器本地处理，不上传到服务器。

**关键词**: 眼动追踪，WebGazer，单摄像头，浏览器端追踪，数据可视化，隐私保护

---

## 1. 当前实现范围

当前项目由静态文件组成：

| 文件或目录 | 作用 |
| --- | --- |
| `index.html` | 页面结构、各阶段屏幕、按钮和表单 |
| `style.css` | 全部视觉样式和响应式布局 |
| `app.js` | 应用状态、校准流程、追踪流程、报告绘制、导入导出 |
| `webgazer.js` | 本地 WebGazer 追踪引擎 |
| `mediapipe/face_mesh/` | `webgazer.js` 内部 Face Mesh 追踪器需要加载的运行资源 |
| `.github/workflows/pages.yml` | GitHub Pages 静态站部署流程 |
| `.nojekyll` | 让 GitHub Pages 原样发布静态资源 |

此前的双摄像头实验已经回退。项目中保留的 `mediapipe/face_mesh/` 目录不是双摄像头残留，而是当前 `webgazer.js` 通过 `faceMeshSolutionPath: "./mediapipe/face_mesh"` 读取的依赖资源。发布到 GitHub Pages 时必须保留该目录。

## 2. 系统架构

本工具是一个无构建步骤的静态单页应用：

```text
index.html
  ├─ 隐私说明弹窗
  ├─ 摄像头预览调整屏
  ├─ 横版 A4 纸面 9 点校准屏
  ├─ 横版 A4 标识追踪操作屏
  └─ 数据回顾与报告屏

app.js
  ├─ State 全局状态
  ├─ WebGazer 初始化
  ├─ 横版 A4 纸面坐标映射
  ├─ 校准点生成与采样
  ├─ 图片上传与选择
  ├─ 眼动数据采集
  ├─ 热力图/轨迹图绘制
  └─ CSV/JSON 导入导出

webgazer.js + mediapipe/face_mesh/
  └─ 摄像头视频流、眼部特征提取和本地回归预测
```

系统不依赖前端框架、构建工具或外部样式框架。直接通过本地静态服务器或 GitHub Pages 访问即可运行。

## 3. 用户流程

1. 用户打开页面，默认进入首页。
2. 点击“开始校准”后，页面显示隐私说明。
3. 用户同意后，浏览器请求摄像头权限并初始化 WebGazer。
4. 初始化成功后进入摄像头调整屏，用户根据预览让双眼位于画面中央。
5. 用户点击“进入九点校准”，参与者依次注视打印横版 A4 校准纸上的 3×3 点位；操作员在屏幕上的横版 A4 映射界面确认对应点。每个点需要确认 3 次，也可按 `Space`、`Enter` 或 `0` 确认。
6. 校准完成后返回首页，用户上传并选择与打印横版 A4 标识一致的图像。
7. 点击“开始追踪”后，参与者观看打印横版 A4 标识；屏幕仅作为操作员监看界面，系统记录横版 A4 纸面坐标。
8. 点击右上角停止按钮后进入报告页。
9. 用户可以切换热力图和视线轨迹图，设置指定时间段，开关背景图叠加，并导出透明 PNG 图层。
10. 用户也可以导出单次 CSV、全部 CSV 或完整 JSON 存档。

## 4. 核心实现

### 4.1 WebGazer 初始化

`app.js` 中的 `initWebGazer()` 是唯一初始化入口。它会：

- 检查 `webgazer` 是否加载成功。
- 检查浏览器是否支持 `navigator.mediaDevices.getUserMedia`。
- 主动请求一次摄像头权限，用于明确捕获权限拒绝、无摄像头或摄像头占用等错误。
- 调用 `webgazer.setRegression('ridge').saveDataAcrossSessions(false).begin()`。
- 注册 `setGazeListener`，在校准和追踪屏幕中分别更新视线光标、采集追踪点。
- 调用 `webgazer.removeMouseEventListeners()`，避免 WebGazer 默认鼠标事件干扰校准数据。
- 隐藏 WebGazer 自带视频预览和预测点，但保持视频元素处于可处理状态。

### 4.2 摄像头调整屏

校准前增加了独立的摄像头调整屏。该屏不重新请求摄像头，而是复用 WebGazer 创建的 `#webgazerVideoFeed.srcObject`，同步到 `#camera-adjust-video` 中，方便用户在 9 点校准前检查眼睛是否位于画面中央。

相关函数：

- `startCalibrationFromHome()`
- `beginCameraAdjustmentScreen()`
- `syncCameraAdjustmentPreview()`
- `beginCalibrationScreen()`

### 4.3 横版 A4 坐标映射

系统使用横版 A4 纸张的物理比例 `297mm × 210mm` 建立内部纸面坐标系。屏幕上的横版 A4 面板不是刺激内容，而是操作员用来确认纸面点位的控制界面。WebGazer 训练时仍接收数值坐标，但这些坐标代表纸面点映射后的虚拟坐标，而不是参与者实际注视的屏幕点。

追踪阶段每个数据点会同时保存：

- `x` / `y`：WebGazer 输出的内部虚拟坐标。
- `a4X` / `a4Y`：归一化 A4 纸面坐标，范围为 `0..1`。
- `a4Xmm` / `a4Ymm`：以毫米表示的 A4 纸面位置。
- `onPaper`：该点是否落在 A4 纸面映射范围内。

报告绘制时优先使用 `a4X` / `a4Y`，直接映射到上传图像的宽高，因此不再依赖屏幕中图片显示的位置。

### 4.4 9 点校准

校准点由 `CALIB_POSITIONS` 定义，使用 3×3 布局。每个点需要 3 次确认。确认时调用：

```js
webgazer.recordScreenPosition(sx, sy, 'click');
```

这样只有用户明确点击或按键确认的点会进入校准数据，减少鼠标移动带来的偏差。

### 4.5 数据采集

追踪阶段只在 `State.isTracking === true` 时记录数据。每个点包含：

```js
{
  x: number,
  y: number,
  a4X: number,
  a4Y: number,
  a4Xmm: number,
  a4Ymm: number,
  onPaper: boolean,
  timestamp: number
}
```

一次追踪结束后，数据会被保存到当前参与者的 `runs` 中。数据默认保存在页面内存里，刷新页面后不会自动恢复；如需保留，需要导出 JSON 存档。

### 4.6 数据可视化

报告页使用 `report-canvas` 绘制两种视图：

- 热力图：用离屏 Canvas 累积密度，再按分位数归一化映射到蓝、绿、黄、橙、红色阶。
- 视线轨迹图：对数据点降采样后绘制路径、序号、起点和终点。
- 时间段筛选：按本次追踪开始后的秒数过滤点位，例如 `5` 到 `30` 秒。
- 背景图叠加：预览时可显示或隐藏上传的 A4 标识图像。
- 透明图层导出：导出与上传图像同尺寸的 PNG 透明层，便于在外部软件中叠加。

## 5. 数据与隐私

- 摄像头画面只在浏览器本地用于 WebGazer 追踪。
- 项目没有服务器端代码，不上传摄像头画面或眼动数据。
- WebGazer 的跨会话保存已关闭：`saveDataAcrossSessions(false)`。
- 用户可以导出 CSV 或 JSON 文件；导出操作由浏览器本地生成下载文件。
- 导入 JSON 存档时，项目会校验并规范化参与者、追踪记录和点位数据。

## 6. 运行与发布

本项目需要通过 `localhost`、HTTPS 或 GitHub Pages 访问，不能直接依赖普通 `file://` 路径运行摄像头权限流程。

本地检查可使用：

```bash
python3 -m http.server 4174
```

然后访问：

```text
http://localhost:4174/
```

发布到 GitHub Pages 时，使用仓库根目录作为静态站点根目录，并保留 `.nojekyll`，确保 `mediapipe/face_mesh/` 下的资源可以被原样访问。

---

## 7. 当前限制

- 准确度受光线、摄像头质量、用户头部姿态和眼镜反光影响。
- 浏览器自动化环境通常无法完整验证真实摄像头预览，需要人工授予摄像头权限后测试。
- 当前没有实现双摄像头选择、头部姿态独立建模或虹膜特写摄像头融合。
- 页面刷新后内存中的参与者数据会丢失，除非用户先导出 JSON 存档。

---

## 8. 建议维护规则

- 不要删除 `mediapipe/face_mesh/`，除非同时替换 `webgazer.js` 并确认新版本不再需要这些文件。
- 文档中不要再描述未实现的框架、构建流程或追踪能力，除非代码确实重新引入这些能力。
- 修改校准流程时，应保留“首页 → 隐私确认 → 摄像头调整 → 9 点校准 → 首页”的阶段顺序。
- 修改报告绘制后，至少运行 `node --check app.js`、`git diff --check`，并用本地静态服务器加载首页检查控制台错误。
