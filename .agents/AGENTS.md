# Project rules: 三页并显幻灯片排版与设计规范

在三页同时显示的特殊幻灯片模式下（当前页面居中显示，两侧邻页等比例缩小并淡出），因为整体画面有大约 30% 左右的缩小比例，如果继续使用传统 PPT 的小字号或复杂排版，会导致内容在宣讲中完全无法阅读。

为了确保所有文字具备极高可读性，项目下的所有 AI 助手在修改、生成幻灯片时必须严格遵守本规范。

---

## 0. 修改任务等级与最小化流程

所有修改先按影响范围分级。**默认使用轻量修改（L）**；只有触及重大视觉或共享运行时风险时才使用重度修改（H）。分级以实际影响为准，不以文件类型为准：修改 HTML 不自动等于重度，修改 CSS 也不自动等于重度。

### L：轻量修改（默认）

适用范围：文字、翻译、标签、单个间距或颜色、既有组件内的局部字号调整、明确原因的单点修复、文档、测试规则，以及不改变页面结构和视觉构图的局部代码。

最小流程：

1. 只检查相关文件、相关选择器和 `git status`，不做全仓库审查。
2. 直接修改，不为单点改动另建长计划或拆分无关任务。
3. 只运行与改动直接相关的最小验证，再运行 `git diff --check`。默认不启动服务器、不截图、不跑全量测试。
4. 检查一次差异后立即提交一个聚焦 commit，并报告修改文件和验证命令。

轻量修改最多进行一次实现和一次验证；验证失败时只针对失败点修复，不扩展为无关清理。

### H：重度修改

触发条件：改变页面构图或网格、图片容器显示模式/裁切/比例、导航或轮播、全局 CSS、字体缩放、动画运行时、多个页面的一致性，或任何可能影响相邻页面的视觉改动。用户明确要求截图审查时也使用 H。

最小流程：

1. 先确定受影响页面和共享样式边界，只建立足以执行的短计划。
2. 修改后先跑针对性的静态检查或回归测试。
3. 在一个桌面尺寸和一个窄屏尺寸截图审查受影响页面；只审查受影响页面，不默认截图全套 19 页。
4. 根据截图进行一次集中优化；只有发生视觉改动时才重新截图。
5. 运行与共享行为直接相关的测试，执行 `git diff --check`，检查差异后提交一个聚焦 commit。

重度流程的目标是“修改 → 截图审查 → 必要优化”，不是反复截图或无边界的全项目 QA。

### 自动升级规则

轻量修改过程中只要发现布局、图片、导航、全局样式或相邻页面受到影响，立即升级为 H；升级后补做截图审查，不需要重新开始已经完成的局部修改。反之，单纯文字或文档修改不得被无故升级为 H。

### 两档共同规则

- 每次实际修改都必须有独立 Git 提交；只暂存本次涉及的文件。
- 不覆盖、回滚或暂存用户已有的改动、未跟踪资料和生成文件。
- 需求明确时直接执行，不反复询问选择；只有无法安全判断或存在真实阻塞时才提问。
- 默认不创建额外计划、截图或报告；只有 H 或确有长期复用价值时才新增记录。
- 完成汇报只保留等级、改动范围、实际验证和 commit，避免重复叙述过程。

## 1. 字体字号规范 (基于 1200px 逻辑画布)

幻灯片布局使用固定的 `1200px * 900px` 逻辑坐标，所有的文字大小必须采用绝对的 `px` 单位，不得使用 `vw` 等视口相对单位。

### 📏 核心字号下限阶梯
- **主标题（Slide Title / `.h-xl-zh`）**：
  - **建议字号**：`52px - 56px`
  - **极限下限**：`50px`
- **卡片级标题 / 栏目标题 / 节标题 (`.t-h-prod`, `h3`)**：
  - **建议字号**：`32px - 36px`
  - **极限下限**：`30px`
- **正文大段描述 (`.t-body`)**：
  - **建议字号**：`26px - 28px`
  - **极限下限**：`24px`
- **小字正文 / 列表项 / 卡片内部描述 (`.t-body-sm`)**：
  - **建议字号**：`22px - 24px`
  - **极限下限**：`20px`
- **底部来源说明 / 辅助文本 (`.t-meta`, `.t-helper`)**：
  - **建议字号**：`16px - 18px`
  - **极限下限**：`14px`

## 2. 字重与对比度规范

- **字重分级**：
  - 页面大字标题与数字：优先使用细体（`200` 或 `300`），大面积展示时字重最多不超过 `600`，防止在缩放下笔画黏连。
  - 正文与列表段落：统一使用高对比的 `400`（Regular）。需要加粗强调时使用 `600` (SemiBold)。
- **色彩对比度**：
  - 所有正文必须使用极高对比度的颜色，通常为纯黑（`color: var(--text-primary)`）或近黑。
  - 严禁在白底卡片中使用浅灰字，或者在暗色背景中使用低亮度彩色字。

---

## 3. 布局与版式规则

- **积极分页 (Active Pagination)**：
  - 页面排版不应追求多、满，而应积极进行分页处理。
  - 单页幻灯片承载的核心内容板块（如 Card）**禁止超过 2 个**（如三栏布局在放大字号后会非常拥挤，必须将内容精炼或分裂为独立页面）。
- **上下布局优先**：
  - 鉴于 4:3 比例画布左右宽度较窄，排版结构必须以**上下行排版**为首选。
  - 单行文本的字符限制在 `55ch - 60ch` 以内，避免长句换行错乱。
- **防止多语言文本溢出**：
  - 由于英语和西班牙语译文普遍比中文译文长 20%~40%，所有卡片容器和正文区块必须预留至少 **30% 的空白溢出区 (Safety Buffer)**，禁止将卡片填得过满。

---

## 4. 图标与图画辅助规则

- **矢量图标增强**：所有的要点列表和卡片在可能的情况下均应附带对应的 Lucide 图标（大小在 `24px - 28px` 之间），用于打破纯文本的视觉单调感。
- **插图比例**：插图或实机截图（如校准、标注界面）宽度应不低于 `24vw`，高度不低于 `11vh`，配有 10px 边角圆弧（`.frame-img`）和高对比的居中说明字幕。

---

## 5. 禁忌红线 (Red Lines)

1. **红线一**：禁止使用任何带有装饰线或复杂花纹的卡片背景，一律使用简洁现代的纯色细边框白底卡片。
2. **红线二**：严禁在幻灯片中启用 `line-clamp` 截断，所有文字必须完全可见，溢出应通过优化字数或分页解决。
3. **红线三**：禁止在幻灯片底部指示器中重复出现 `研究背景 · ` 等章节名称前缀，仅显示当前幻灯片的具体标题和页码。
4. **红线四**：禁止在数据页中将所有指标平均平铺展示，必须选出 1 个最核心的关键指标做 Hero 放大处理。
5. **红线五**：禁止配图出现生硬裁切、变形或内部上下留白死角，必须锁定 `1.414 / 1`（或图示原生比例）无死角贴合容器。
6. **红线六**：严禁使用贪婪的 `margin: auto` 破坏垂直韵律导致底部空置巨大留白，必须严格遵循“四处间距完全均等律”。

## 6. 新增页面与深度数据分析专有设计准则

为了确保未来所有新增页面（特别是实验数据、学术图解、行为分析类页面）维持极致的美感、高可读性与专业水准，必须严格遵循以下 7 大设计模式：

### 6.1 面向快速理解的极简动态插图 (3-Second Minimalist Animations)
- **目标受众**：报告面向初次接触该研究的听众，必须在 3 秒内传递本页的核心分析对象。
- **视觉风格**：极简纯线条 SVG 动画（如眼球左右移动、动线循迹、回视环流、正态推断曲线），保持与全套幻灯片一致的极简现代风。
- **摆放位置**：统一置于标题栏右侧的 `.analysis-anim-badge` 中，包含微型等宽标签（如 `SCANPATH`、`SACCADES`、`RE-READING`、`INFERENCE`）与 30px 高度内的精致微动矢量动画。
- **目录复用**：全局导航/目录页（Overview / Menu Slide）必须复用各子阶段的动态插图微标，形成视觉认知闭环。

### 6.2 主次分明的 Hero 数据呈现架构 (Hero KPI + Subordinate Stack)
- **拒绝平均平铺**：每一数据分析页必须挑选出**一个最核心、最具震撼力的数据**作为 Hero 焦点放大呈现。
- **左右分栏布局与卡片材质统一**：
  - **左侧次要数据栏（Sub-Stack）**：固定宽度（如 `350px`），垂直等分排布 3 行紧凑型小卡片（每行高 `42px~46px`，字号 `20px`，标签 `12px Mono`，白底细边框 `1px solid var(--border-subtle)`）；
  - **右侧巨幅 Hero 卡片（Hero Card）**：占据主宽度，采用统一白底与细边框材质（`background: #fff; border: 1px solid var(--border-subtle)`，严禁使用突兀的绿色大底色或绿色外框），核心数字使用 `50px` 超大字号（字重 `200`，颜色 `var(--accent)`），配有 `15.5px` 粗体标题与 `13.5px` 的结论副标。

### 6.3 真实标牌配图与多维度表现力强化 (Expressive Botanical Evidence)
- **说明对象直观化**：配图主要目的为清晰解说分析了什么标牌与哪些区域，必须使用高清晰度的真实植物标牌（如 Bougainvillea 对照组与改良组）。
- **比例与容器**：
  - 严禁裁切原图边缘，容器采用精确的 `aspect-ratio: 1.414 / 1`，保证图片与图框边框像素级贴合，无内部黑白死角；
  - 容器外观统一为纯白底细边框（`1px solid var(--border-subtle)`），不使用带色外框；
  - 配图顶部不得放置冗余标题条，保持画面通透纯粹。
- **丰富表现力叠加层**：严禁仅放置静态裸图，必须根据分析类型使用半透明遮罩、矢量线条、标注与高光增强说服力：
  - **动线时序（TTFF）**：叠加编号动线节点（`①` $\to$ `②` $\to$ `③` $\to$ `④`）与半透明 TTFF 秒数提示胶囊；
  - **动力学眼跳（Saccades）**：对照组叠加红色发散视野遮罩与眼跳双向矢量线；实验组叠加局部模块 AOI 聚焦虚线框与收窄标签；
  - **回视重读（Re-reading）**：简单标牌叠加快速单向下行流线；深度标牌叠加环形多点回视轨迹（$\circlearrowleft$）与高光激活框；
  - **推断统计（Synthesis）**：对照组叠加长文本注视壁垒红色警示遮罩；实验组叠加身体关联 R 区绿色高光光晕与平稳转导流线。

### 6.4 垂直空间“四处间距完全均等律” (Equal Four-Tier Vertical Spacing)
- **三段式弹性架构**：页面根容器 `.analysis-data-slide` 内部采用三段顶级容器结构：
  1. 顶部标题栏（`.analysis-header-row`）
  2. 中间核心主体（`.analysis-body-group`，内部包含 Hero 数据网格与配图实证两行）
  3. 底部结论栏（`.analysis-ledger-v2`）
- **间距均等分布**：根容器设置 `justify-content: space-between` 与对称内边距（`padding: 54px 48px`），确保以下 4 处纵向空间完全均等：
  $$\text{Top Padding (54px)} = \text{Gap 1 (54px)} = \text{Gap 2 (54px)} = \text{Bottom Padding (54px)}$$
- **彻底消除死角留白**：通过上述均等律，页面垂直方向从上到下饱满分布，彻底根除下方空置大留白或上方部件拥挤挤压的视觉失衡。

### 6.5 底部结论栏规范 (Two-Row Single-Line Ledger & No-Divider Principle)
- **单行极简版式**：采用双行结论栏，每行分为两列：
  - **左列（380px）**：微型等宽标签（如 `[RANK 1ST]`、`[PACING]`、`[REVISIT]`、`[EVIDENCE]`、`[NEUTRAL]`）+ 粗体小标题；
  - **右列（自适应）**：精炼客观的学术结论正文（`15px` 高对比度文本）。
- **无分割线原则**：去除结论栏上方分割线，尽可能少使用装饰性线条，完全依靠纯粹的均等垂直间距建立优雅的层次感。

### 6.6 浏览器实机自截图审查规范 (Visual QA Loop)
- **严禁盲改**：任何触及布局结构、字号层级、多语言排版、间距疏密或配图标注的修改，必须运行 `node scripts/build.mjs && node scratch/capture_slides.mjs`。
- **截图自检**：在提交前必须调用 `view_file` 实际查看生成的渲染截图，确认无元素裁切、无文字溢出、间距匀称且色彩对比度良好后方可交付。
