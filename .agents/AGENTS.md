# Project rules: 三页并显幻灯片排版与设计规范

在三页同时显示的特殊幻灯片模式下（当前页面居中显示，两侧邻页等比例缩小并淡出），因为整体画面有大约 30% 左右的缩小比例，如果继续使用传统 PPT 的小字号或复杂排版，会导致内容在宣讲中完全无法阅读。

为了确保所有文字具备极高可读性，项目下的所有 AI 助手在修改、生成幻灯片时必须严格遵守本规范。

---

## 0. 修改任务等级与最小化流程

所有修改先按影响范围分级。**默认使用轻量修改（L）**；只有触及重大视觉或共享运行时风险时才使用重度修改（H）。分级以实际影响为准，不以文件类型为准：修改 HTML 不自动等于重度，修改 CSS 也不自动等于重度。

### L：轻量修改（默认）

适用范围：文字、翻译、标签、单个间距或颜色、既有组件内的局部字号调整、明确原因的单点修复、文档、测试规则，以及不改变页面结构和视觉构图的局部代码。

最小流程：

1. 只检查相关文件、相关选择器和 `git status`，不做全仓库审查。
2. 直接修改，不为单点改动另建长计划或拆分无关任务。
3. 只运行与改动直接相关的最小验证，再运行 `git diff --check`。默认不启动服务器、不截图、不跑全量测试。
4. 检查一次差异后立即提交一个聚焦 commit，并报告修改文件和验证命令。

轻量修改最多进行一次实现和一次验证；验证失败时只针对失败点修复，不扩展为无关清理。

### H：重度修改

触发条件：改变页面构图或网格、图片容器显示模式/裁切/比例、导航或轮播、全局 CSS、字体缩放、动画运行时、多个页面的一致性，或任何可能影响相邻页面的视觉改动。用户明确要求截图审查时也使用 H。

最小流程：

1. 先确定受影响页面和共享样式边界，只建立足以执行的短计划。
2. 修改后先跑针对性的静态检查或回归测试。
3. 在一个桌面尺寸和一个窄屏尺寸截图审查受影响页面；只审查受影响页面，不默认截图全套 19 页。
4. 根据截图进行一次集中优化；只有发生视觉改动时才重新截图。
5. 运行与共享行为直接相关的测试，执行 `git diff --check`，检查差异后提交一个聚焦 commit。

重度流程的目标是“修改 → 截图审查 → 必要优化”，不是反复截图或无边界的全项目 QA。

### 自动升级规则

轻量修改过程中只要发现布局、图片、导航、全局样式或相邻页面受到影响，立即升级为 H；升级后补做截图审查，不需要重新开始已经完成的局部修改。反之，单纯文字或文档修改不得被无故升级为 H。

### 两档共同规则

- 每次实际修改都必须有独立 Git 提交；只暂存本次涉及的文件。
- 不覆盖、回滚或暂存用户已有的改动、未跟踪资料和生成文件。
- 需求明确时直接执行，不反复询问选择；只有无法安全判断或存在真实阻塞时才提问。
- 默认不创建额外计划、截图或报告；只有 H 或确有长期复用价值时才新增记录。
- 完成汇报只保留等级、改动范围、实际验证和 commit，避免重复叙述过程。

## 1. 字体字号规范 (基于 1200px 逻辑画布)

幻灯片布局使用固定的 `1200px * 900px` 逻辑坐标，所有的文字大小必须采用绝对的 `px` 单位，不得使用 `vw` 等视口相对单位。

### 📏 核心字号下限阶梯
- **主标题（Slide Title / `.h-xl-zh`）**：
  - **建议字号**：`52px - 56px`
  - **极限下限**：`50px`
- **卡片级标题 / 栏目标题 / 节标题 (`.t-h-prod`, `h3`)**：
  - **建议字号**：`32px - 36px`
  - **极限下限**：`30px`
- **正文大段描述 (`.t-body`)**：
  - **建议字号**：`26px - 28px`
  - **极限下限**：`24px`
- **小字正文 / 列表项 / 卡片内部描述 (`.t-body-sm`)**：
  - **建议字号**：`22px - 24px`
  - **极限下限**：`20px`
- **底部来源说明 / 辅助文本 (`.t-meta`, `.t-helper`)**：
  - **建议字号**：`16px - 18px`
  - **极限下限**：`14px`

## 2. 字重与对比度规范

- **字重分级**：
  - 页面大字标题与数字：优先使用细体（`200` 或 `300`），大面积展示时字重最多不超过 `600`，防止在缩放下笔画黏连。
  - 正文与列表段落：统一使用高对比的 `400`（Regular）。需要加粗强调时使用 `600` (SemiBold)。
- **色彩对比度**：
  - 所有正文必须使用极高对比度的颜色，通常为纯黑（`color: var(--text-primary)`）或近黑。
  - 严禁在白底卡片中使用浅灰字，或者在暗色背景中使用低亮度彩色字。

---

## 3. 布局与版式规则

- **积极分页 (Active Pagination)**：
  - 页面排版不应追求多、满，而应积极进行分页处理。
  - 单页幻灯片承载的核心内容板块（如 Card）**禁止超过 2 个**（如三栏布局在放大字号后会非常拥挤，必须将内容精炼或分裂为独立页面）。
- **上下布局优先**：
  - 鉴于 4:3 比例画布左右宽度较窄，排版结构必须以**上下行排版**为首选。
  - 单行文本的字符限制在 `55ch - 60ch` 以内，避免长句换行错乱。
- **防止多语言文本溢出**：
  - 由于英语和西班牙语译文普遍比中文译文长 20%~40%，所有卡片容器和正文区块必须预留至少 **30% 的空白溢出区 (Safety Buffer)**，禁止将卡片填得过满。

---

## 4. 图标与图画辅助规则

- **矢量图标增强**：所有的要点列表和卡片在可能的情况下均应附带对应的 Lucide 图标（大小在 `24px - 28px` 之间），用于打破纯文本的视觉单调感。
- **插图比例**：插图或实机截图（如校准、标注界面）宽度应不低于 `24vw`，高度不低于 `11vh`，配有 10px 边角圆弧（`.frame-img`）和高对比的居中说明字幕。

---

## 5. 禁忌红线 (Red Lines)

1. **红线一**：禁止使用任何带有装饰线或复杂花纹的卡片背景，一律使用简洁现代的纯色细边框白底卡片。
2. **红线二**：严禁在幻灯片中启用 `line-clamp` 截断，所有文字必须完全可见，溢出应通过优化字数或分页解决。
3. **红线三**：禁止在幻灯片底部指示器中重复出现 `研究背景 · ` 等章节名称前缀，仅显示当前幻灯片的具体标题和页码。
